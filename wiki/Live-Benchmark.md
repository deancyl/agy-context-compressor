# 🧪 内置基准测试与防降智红线 (Live Benchmark & Anti-Degradation)

为了让开发者能够亲眼验证压缩效果，本项目内置了 5 大真实工程场景的自动化基准测试套件，并通过代码级的 `assert` 严格断言“防降智安全红线”。

---

## 一、 一键运行基准测试

在项目根目录下直接运行：

```bash
npm run benchmark
# 或直接调用：
node bin/agy-compressor.js benchmark
```


## 二、 五大场景设计与“防降智安全断言”

| 测试场景 | 模拟真实场景 | 压缩动作 | 防降智红线断言机制（必须 100% 通过） |
| :--- | :--- | :--- | :--- |
| **Card 1: 测试套件去噪** | 80 个测试用例通过，中间穿插 1 个抛出致命异常的失败用例。 | 折叠 80 个通过绿标，输出 `[Test suite: 80 passed tests folded]`。 | **报错保真断言**：断言最终压缩文本必须 100% 包含原失败用例的名称、`AssertionError` 堆栈与出错代码行号，严禁错杀任何报错！ |
| **Card 2: 锁文件 Diff 折叠** | `package-lock.json` 中 150 行依赖版本哈希变动。 | 将漫长哈希行折叠为结构摘要并生成 CCR 存储块。 | **冲突标记断言**：断言如果文本中出现 `<<<<<<< HEAD` 冲突标记，系统必须立即**全额放弃折叠**，确保模型能看到冲突上下文！ |
| **Card 2: SmartCrusher 采样** | 接口返回包含 100 个同构数据项的超大 JSON 数组。 | 采样保留前 5 项、后 3 项与数据 Schema。 | **结构自愈断言**：断言必须生成合法的 JSON 占位，且全量数据必须完整落盘至本地 CCR。 |
| **Card 6: Aider 词法骨架** | 包含 20 个函数、类、默认对象参数（`cfg = {}`）的源文件。 | 提取函数签名、行号跨度并折叠函数体。 | **签名保真断言**：断言默认参数里的 `{}` 绝对不得被粗暴切除，行号跨度必须覆盖实际代码行。 |
| **Card 7: DCP 历史剪枝** | 同一文件在不同轮次被重复读取，随后被修改覆写。 | 剪除旧版过期读取，保留最新快照。 | **最新版本断言**：断言最新的修改行必须 100% 完整保留，旧快照转移至 CCR 暂存待查。 |

## 三、 CCR (Content-Compressed Retrieval) 可逆性验证

许多开发者担心：“如果模型真的需要看被折叠的某一行通过日志怎么办？”

本项目设计了 **CCR 可逆机制** 作为绝对安全网：
1. 任何被折叠的大文本，都会在被折叠处附带一个唯一的哈希标识符，例如：
   ```text
   [Test suite: 80 passed tests folded (✓ / PASS / ok)] [CCR: agy_retrieve_chunk(chunk_id="chk_eada445f")]
   ```
2. 原文已完整保存在本地（默认保留最多 300 块，自动 LRU 淘汰）；
3. 智能体若产生疑问，可通过 MCP 工具 `agy_retrieve_chunk(chunk_id="chk_eada445f")`，在 **`< 2ms`** 内瞬间还原全文。信息只是从宝贵的模型上下文移到了本地高速存储中，**零实质信息损耗**。
